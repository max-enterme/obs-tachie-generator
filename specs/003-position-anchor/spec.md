# 立ち絵の基準位置(アンカー)を9通りから選ぶ ＋ 画像クロップ

> spec.md — フィーチャーの「何を・なぜ」。正本はこのテキストと GitHub(Feature issue)。

## 目的
立ち絵を置く**基準(アンカー)を 左/中央/右 × 上/中央/下 の9通りから選べる**ようにする。
現状の「左端・下端からの px」固定をやめ、右寄せ・中央寄せ・上寄せを解像度非依存で指定できる状態にする。

あわせて、**取り込んだ立ち絵画像を矩形でクロップ(切り抜き)できる**ようにする。
アンカーは「画像の外形」を基準にするため、**透明余白を含んだ画像ではアンカーが余白の分だけズレる**。
クロップ(特に透明余白の自動トリム)はアンカーが意図どおり効くための前提であり、同じフィーチャーで入れる。

## 背景 / 課題
- 現状の出力は `position: fixed; left: <X>px; bottom: <Y>px;` の決め打ち
  ([`src/lib/generateCss.ts:132`](../../src/lib/generateCss.ts))。基準は常に**左下**。
- **右端に置くのが実質できない。** 「キャンバス幅 − 立ち絵幅 − 余白」を人間が計算して `left` に入れる必要があり、
  OBS のキャンバス解像度や立ち絵の幅を変えるたびに破綻する。
- **中央寄せも同様。** 幅を「原寸」(= `width` 未指定)で使っている場合は、そもそも人間が計算できない。
- 複数人を左右に振り分ける配置(自分は右下・相手は左下 など)が定番だが、今は数値の当てずっぽうになる。
- **画像の透明余白がアンカーを壊す。** 配布・書き出しされた立ち絵 PNG は、上下左右に透明の余白が付いていることが多い。
  アンカーが見るのは画像の外形(余白込み)なので、右下アンカーにしても「絵の右下」ではなく「余白の右下」が揃い、
  見た目は画面端から浮く。オフセット px で人間が引き算して打ち消す羽目になり、アンカーを入れた意味が薄れる。
- **一部だけ使いたい場面がある。** 全身の1枚から「バストアップだけ出す」ような使い分けが、
  今は画像編集ソフトで別ファイルを作るしかない。取り込み後にツール内で切れない。

## スコープ
- **含む**:
  - プリセットに **横アンカー(`left`/`center`/`right`) × 縦アンカー(`top`/`middle`/`bottom`)** を持つ。
  - オフセット(px)の意味を**選んだアンカーからの距離**に変更する(右アンカーなら右端から、など)。
    中央は `50%` + `transform: translate()`。
  - **発話演出(ぴょこぴょこ)との `transform` 衝突の解消**(下記「降りる箇所」)。
  - **プレビューがアンカーに追従**する(貼る前に右寄せ・中央寄せの見え方を確認できる)。
  - **後方互換**: アンカー未設定の既存プリセット(localStorage 保存分)は **左下** として読み、
    出力が従来と一致する。
  - UI: 9通りを選ぶコントロール(3×3 のグリッド等)とオフセットのラベル追従
    (「左端からの距離」→ アンカーに応じた文言)。
  - **画像の矩形クロップ**: 取り込み済みの立ち絵に対し、`x` / `y` / `幅` / `高さ` の矩形で切り抜く。
    指定はプレビュー上のドラッグ + 数値入力の両方。
  - **透明余白の自動トリム**: 「余白を詰める」1操作で、アルファ 0 の外周を落として絵の実体に切り詰める。
    アンカーが絵の実体基準で効くようにするための主役機能。
  - **切り抜きは取り込み時に canvas で焼き込む**(結果を data URI にして `imageUrl` を差し替える)。
    出力CSS の形は**変わらない**(`generateCss` は無改修)。理由は下記「降りる箇所」。
  - クロップ後の**寸法(px)を UI に表示**する(幅を「原寸」で使うときの目安になるため)。
  - クロップ結果が**プレビュー・出力CSS の双方に反映**される(焼き込みなので自動的に一致する)。
- **含まない**:
  - **非破壊クロップ**(原本を保持して何度でもやり直す)。原本 + 切り抜き後の2枚を localStorage に持つと
    容量が倍になり現実的でない(→「降りる箇所」)。**やり直しは再取り込み**とする。
  - 円形・自由形状のマスク、角丸、フェード。矩形のみ。
  - 表情差分のように**1プリセットが複数のクロップを持つ**構成(画像の複数登録は別フィーチャー)。
  - 9スライス的な引き伸ばし(境界を固定した拡大)。クロップは切り抜きだけで、拡縮は既存の `width` が持つ。
  - **キャンバス解像度の切替UI**。プレビューは 1920×1080 基準のまま(アンカー指定の効果は解像度非依存なので、
    このフィーチャーの受け入れには不要)。
  - **名前ラベル(002)のアンカー対応**。名前は 002 の「立ち絵からの相対位置」に従うため、
    立ち絵アンカーの変更に自動追従すれば足りる。
  - 回転・スケール・反転などの変形。
  - まとめ版 `generateCombinedCss` のアンカー対応(UI から呼ばない温存コード。型の整合だけ取る)。

## 受け入れ条件
- [ ] 9通りのアンカーを UI で選べ、出力CSSに反映される(`left`/`right`/`top`/`bottom`/`50%` の出し分け)
- [ ] **中央寄せ + ぴょこぴょこ ON で立ち絵が飛ばない**(中央寄せの `transform` がアニメで打ち消されない)
- [ ] 右・上アンカー指定時、OBS キャンバス解像度が変わっても**指定した端からの距離が保たれる**
- [ ] 幅が「原寸」(`width` 未指定)でも中央寄せが成立する
- [ ] **既存の保存済みプリセット**(アンカー無し)が左下として読め、出力が従来と**バイト一致**する
- [ ] プレビューがアンカーに追従する
- [ ] 9通り × 発話演出の組み合わせを vitest で固定する(既存テストは壊さない)
- [ ] 画像を**矩形でクロップ**でき、結果がプレビューと出力CSS(埋め込み data URI)の両方に反映される
- [ ] **「余白を詰める」で透明余白が落ち**、右下アンカーにしたとき**絵の右下**が指定オフセットで画面端に付く
- [ ] クロップ後に `width` 未指定(原寸)で使うと、**クロップ後の寸法**が原寸として扱われる
- [ ] **クロップ矩形の正規化**(画像外へのはみ出し / 負値 / 幅0 / 小数)が純粋関数で保証され、vitest で固定される
- [ ] **透明余白の検出**(全面不透明・全面透明・片側だけ余白)が純粋関数で保証され、vitest で固定される
- [ ] **クロップを使わない既存プリセット**の出力が従来と**バイト一致**する(画像も再エンコードされない)
- [ ] クロップは取り込み時の最大幅リサイズ(`maxWidth`)と併用できる(適用順が決まっていて、結果が破綻しない)

## メモ / 降りる箇所
- **`transform` 衝突が本体の難所。** 中央寄せを `transform: translate(-50%, …)` で実現すると、
  ぴょこぴょこの `@keyframes speak-jump { transform: translateY(…) }`
  ([`src/lib/generateCss.ts:46`](../../src/lib/generateCss.ts)) が中央寄せを**上書きして立ち絵が飛ぶ**。
  対応案は3つ。**実装時に判断する(降りる箇所)**:
  1. **keyframes 側に中央寄せ分を織り込む**(`translate(-50%,-50%) translateY(-8px)` を生成)。
     既に `jumpKind: 'transform' | 'bottom'` の分岐があるのでそこに乗る。**推し。**
  2. 中央寄せのときだけ既存の `KEYFRAMES_JUMP_BOTTOM`(`bottom` を動かす版)に切り替える。
     縦中央アンカーとは相性が悪い。
  3. `calc(50% - 幅/2)` で寄せて `transform` を使わない。**幅が原寸(未指定)だと使えない**ため、
     受け入れ条件「原寸でも中央寄せ」を満たせない。
- **002(名前表示)と同じファイルを触る**(`types.ts` / `generateCss.ts` / `TachiePreview.tsx` / `PresetPanel.tsx`)。
  002 が先行しているので、**002 のマージ後に着手**しないとコンフリクトする。
- `Preset` は localStorage に保存される。アンカー追加は**任意フィールド + 既定値**で入れ、
  既存データの読み込みを壊さないこと。
- **クロップを CSS でやらない理由**(判断済み・覆すなら確認を挟む)。
  立ち絵は `body::after` の `content: var(--img-stand-url-…)` で描く置換要素
  ([`src/lib/generateCss.ts`](../../src/lib/generateCss.ts))。`clip-path: inset()` で見た目は切れるが、
  **要素のボックスは原寸のまま残る**。すると `bottom: 16px` が「切った後の絵の下端」ではなく
  「原画像(余白込み)の下端」からの距離になり、**このフィーチャーの受け入れ条件そのものを壊す**。
  `width` 指定の基準も原寸のままになる。よって **canvas で焼き込む**(`image.ts` の自然な拡張)。
  結果として `generateCss` は無改修で、既存の出力テストに影響しない。
- **破壊的クロップにする(降りる箇所)。** 非破壊にするには原本 dataURI を別に持つ必要があるが、
  取り込みは最大 8MB([`src/lib/image.ts`](../../src/lib/image.ts) `isWithinSizeLimit`)、保存先は
  localStorage(実質 5MB 前後)。原本 + 切り抜き後で**プリセット1件あたりの容量が倍**になり、
  数件で保存が落ちる。よって **`imageUrl` を切り抜き後で上書きし、やり直しは再取り込み**とする。
  UI に「元に戻せません」を明示すること。**非破壊が要るなら原本を IndexedDB に逃がす設計変更が要り、
  それはこのフィーチャーの範囲を超える**(やるなら別 feature として切る)。
- **適用順は クロップ → (既存の)最大幅リサイズ**ではなく、実際は
  **取り込み(URL/アップロード + `maxWidth` リサイズ)→ 保存 → 保存済み画像に対してクロップ**の順になる。
  ユーザーが矩形を引くのは「いま画面に見えている画像」なので、その座標系をそのまま使う。
  クロップ後に再リサイズはしない(二重の再エンコードで劣化するため)。
- **PNG で書き出す。** 立ち絵は透過前提なので JPEG に落とさない。`canvas.toDataURL('image/png')` 固定。
