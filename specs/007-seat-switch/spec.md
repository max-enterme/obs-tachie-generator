# 席の主が入れ替わる(1 つのブラウザソースに候補を並べ、通話にいる人の立ち絵を出す)

> spec.md — フィーチャーの「何を・なぜ」。正本はこのテキストと GitHub(Feature issue)。
> 出所: 依頼「複数人の入れ替わりに対応したcssを出したいなって思うことがある」(2026-10-31)。
> 2 案(A: 席の主が入れ替わる / B: いる人を全員並べる)を示し、本人が **A** を選んだ。B は別 feature(この spec では扱わない)。

## 目的
OBS のブラウザソース 1 つ(= 出力 CSS 1 本)を「**席**」として扱い、席に**候補(ユーザー × 立ち絵プリセット)を順番付きで複数登録**できるようにする。
候補のうち**通話にいる人**の立ち絵が、その席に出る。例: 「ゲスト席」に、その日来た人が出る / 途中で交代する。

## 背景 / 課題
- 今の出力は「1 ペア(ユーザー × プリセット)= 1 ブラウザソース」の常時表示だけ。ゲスト枠のように**日によって・途中で人が変わる**場所には、人数分のブラウザソースを作って OBS 上で付け外しするしかない。
- 1 ソースの擬似要素は使い切り(立ち絵 = `body::after`、名前 = `body::before`。002 / 006)。だから **1 つの席に同時に出せるのは 1 人**。複数人を同時に並べたいなら B 案(全体 URL モード)で、この spec の外。
- 人の特定は `img[src*="avatars/<id>"]`、発話は img の `[class*="Voice_avatarSpeaking__"]`、検知は `:has()`(001〜006 と同じ)。Streamkit の Voice Widget は**通話にいる人の img だけ**を DOM に出すので、「その img があるか」で在室が分かる。

## スコープ
- **含む**:
  - 席の作成・名前変更・削除。席ごとに候補(ユーザー × プリセット)を追加・外す・並べ替え(「上へ」「下へ」)。同じユーザーは 1 つの席に 1 回まで。保存・読み込み。
  - **席に位置を 1 つ持たせる**(基準の位置 = アンカー と、そこからの距離)。誰が出ても同じ位置に出る(2026-10-31 本人回答)。
  - 席 1 つぶんの出力 CSS(コピー・ダウンロード)。位置以外の見た目は、その候補のプリセットに従う: 幅・名前の帯(立ち絵からの相対位置)・口パク(006)・発話演出(ぴょこぴょこ / 枠・後光 / 点滅)・静かな人を暗くする・切り抜き(画像に焼き込み済み)。
  - 席の画面のプレビュー: 候補を押すと、その人の立ち絵を席の位置で映す(2026-10-31 本人回答)。
  - 通話にいる候補が 1 人なら、その人を出す。**2 人以上いるときは、候補リストの上の人を出す**。**誰もいないときは何も出さない**(2026-10-31 本人回答)。
  - 出ている人が話しているときだけ、その人の発話演出・口パクが動く(同じ席の別の候補が話しても、出ている人は動かない)。
  - ユーザー・プリセットを削除したら、その人・そのプリセットを使っている候補も消える。
  - 新しいステップ ④「席(入れ替わり)」。③ は今のまま。
  - README と使い方ガイド(`public/guide.html`)に席の説明を足す。
  - 実ブラウザ(Playwright)での「誰が出るか」の検証。
- **含まない**:
  - 通話にいる人を全員並べる(B 案 / 全体 URL モード)。
  - 席の中で話している人を優先して切り替える(本人回答で「リストの上の人」を採った)。
  - 誰もいないときに既定の立ち絵を出す(本人回答で「何も出さない」を採った)。
  - 「最後にいた人」を残す(CSS では過去の状態を持てない)。
  - プレビューで「誰が通話にいるか」を切り替えて見る(押した候補を映すだけ)。
  - 席の位置欄での「発話演出に要る余白」の注意(005。② の距離欄にだけ出る)。
  - 候補のドラッグでの並べ替え。
  - まとめ版 `generateCombinedCss`(UI から呼ばない温存コード)。

## 受け入れ条件
- [ ] 席に候補 A(1 番目)・B(2 番目)を登録した出力 CSS を実ブラウザ(Chromium)で描くと: A だけ在室 → A の立ち絵だけ / B だけ在室 → B の立ち絵だけ / A と B が在室 → A の立ち絵だけ / 誰もいない → 何も描かれない。
- [ ] 候補ごとにプリセットの位置が違っても、出ている人は**席の位置**に描かれる(A のプリセットが左下・B が下中央でも、席が右下なら A だけ在室・B だけ在室のどちらも右下に出る)。幅はその人のプリセットのまま。
- [ ] A と B が在室で B だけが話しているとき、出ている A の立ち絵は動かない(発話演出・口パクが掛からない)。A が話すと A の発話演出が掛かる。
- [ ] 候補ごとに違う発話演出(跳ねる高さ・枠の色)を設定しても互いに混ざらない(keyframe 名が候補ごとに別)。
- [ ] 名前表示 ON の候補は、その人が出ているときだけその人の名前が出る。
- [ ] 1 人だけの席の出力は、その人の在室中だけ立ち絵が出る(プリセットの「通話にいないときは隠す」の設定に関係なく、席では在室中だけ出す)。
- [ ] 既存の個別出力(③)の CSS は、この feature の前と **1 文字も変わらない**。
- [ ] ④ で席を作り、名前・位置を変え、候補を追加・上へ / 下へ・外すと、出力 CSS が即座に追従する。同じユーザーは 2 回目を追加できない。
- [ ] ④ のプレビューは、押した候補(最初は 1 番目)の立ち絵を席の位置で映す。
- [ ] ① でユーザーを、② でプリセットを削除すると、それを使っていた候補が席から消える。
- [ ] 再読み込みしても席と候補の並びが残る。この feature の前に保存されたデータを読み込んでも壊れず、席 0 件として扱われる。
- [ ] plan.md の `test` が緑。
- [ ] OBS 実機のブラウザソースで、候補 2 人の席の出力を貼り、通話への出入りで出る人が入れ替わる(人手 T6)。

## メモ / 降りる箇所
- 画面の置き場所と並びはモック(ダッシュボード Pages の `obs-tachie-generator/007-seat-mock.html`)で確定する。確定値は plan.md の「確定値」の表。
- 在室の判定は「Streamkit が通話にいる人の img だけを出す」ことに頼る(001 からの前提。公式仕様ではない)。**OBS 実機で、通話から抜けた人の img がすぐ消えるか**は T6 で見る。消えない(しばらく残る)場合の代わりの判定は人が決める。実装側で判定方法を変えない。
- 候補が多い席ほど CSS が長くなる(候補ごとに画像の data URI を埋め込むため)。OBS のカスタム CSS 欄に長さの上限があるかは T6 で候補 3 人の席を貼って見る。入らない場合の対処(画像を外部 URL にする等)は人が決める。
